# LiftLog: notes for coding agents

Strength tracker with a native **SwiftUI iPhone app** (iOS 17+) and a **Next.js web app** that can view *and edit* data. Backend: **Supabase** (Postgres + Auth + row-level security). Public instance: https://liftlog-app-three.vercel.app

## Principles
- iOS only, native SwiftUI. It must install with a free Apple ID (Personal Team): no TestFlight, push notifications or Sign in with Apple.
- Weights are stored as entered, with their unit; never round-trip lb↔kg. Water is stored as entered in fl oz or ml.
- Multi-user: every user table has `user_id` with per-user RLS. Never commit anyone's personal data (measurements, history) in source, fixtures or docs.
- Georgia Tech features only appear when a user's `profiles.campus` is `gatech`: Food → Georgia Tech lists every GT Dining location from dining.gatech.edu plus ~45 restaurants near campus (`shared/food/gatech.json`; dining halls have live Nutrislice menus via `hall`, other places a `menu` brand in `restaurants.json`, `fast-food.json` or `gatech-menus.json`, where items without published nutrition are `estimated` from USDA ingredients and shown with ≈), and **What to eat** (iOS, `DiningPlanner.swift`) picks the best plate per hall for the meal's protein (0.4–0.55 g/kg) and calories. GT's list changes every semester. Same-movement swaps (from `shared/gyms/gatech-crc.json`) are offered to everyone; only the "CRC" wording is campus-specific. The CRC has no ab crunch machine, although its website lists one.
- Body math depends on `profiles.sex` (`male`/`female`): body-fat formulas, plan thresholds and goal (12% / 22%), Wilks/DOTS. While it's null those are hidden behind a hint, never defaulted to male.
- Cardio (built-in Stairmaster and Incline Walk (Treadmill): kind `duration`, muscle `cardio`) is logged as minutes in `sets.duration_seconds`; sets without reps stay out of lifting stats, and cardio-only sessions don't count toward the weekly target. A program day of only cardio (or an empty day named Rest) is a rest day: starting it opens zone-2 presets (`Models/CardioPresets.swift`). The Workout tab is a week strip of the program's days; up next for a 7-day program is today's weekday's routine, shorter programs rotate. Sets are compact lines you type into ("[140] lb × [6]", last time's numbers as placeholders); routine items carry an optional `attachment` ("Rope · top pulley") shown under the exercise name. Built-in programs include the LKC Split (`shared/programs/lkc.json`).
- **Daily targets** (`Energy` in LiftKit, `lib/aesthetics/energy.ts`, fixtures `shared/fixtures/energy-cases.json`): maintenance = Katch-McArdle BMR × 1.55, learned from logged intake vs weight trend once there are 10+ complete days and weigh-ins over 14+ days; target = maintenance ∓ the plan's mid weekly rate, floored at BMR / 1500 (1200 women); protein from the plan, fat ≥ 0.5 g/kg and 25% of kcal, carbs fill the rest; each day's miss is repaid over the next 3 days (capped). iOS counts Apple Health food too; the web only sees LiftLog logs.
- Food screen (iOS): goal bars for calories, macros and steps (Apple Health steps vs LiftKit `Steps.goal`: median of the last 14 days with ≥1,000 steps + 10%, rounded up to 500, 5,000–12,000; steps never leave the phone), water with a remove toggle, goals calendar (protein, water, kcal within 10% → green), tap any logged food to edit, replace (pickers have a pick mode via `\.foodPick`), log again or delete, including past days. Daily reminders (`Services/Reminders.swift`, local notifications, off by default): 10am/1pm/8pm check-ins and 10pm alerts per missed goal, rebuilt on each refresh for today + 6 days.
- Users can delete their account (RPC `delete_account`, web Settings and iOS Settings); `/privacy` describes what's stored. Keep both accurate when adding data.
- Commit in small, incremental steps.

| `shared/` | JSON for both apps: `fixtures/` (golden stats cases), `programs/` (PPL, UL, PPLUL, Arnold, LKC), `gyms/gatech-crc.json`, `food/` (restaurants, snack brands, staples, Georgia Tech places and menus). |

| `scripts/` | `gen_*.py` generators, `supabase_migrate.py`, `load_foods.py`, `vercel_deploy.py`. |
| `docs/` | `INSTALL.md`, `PROGRAMS.md`, `AUTH.md`, `PLAN.md`. |

## Invariants
- **Stats math exists twice**: Swift `LiftKit` and TS `web/src/lib/stats` (+ `aesthetics`). Both test against `shared/fixtures/*.json`. Change both and add a fixture case.
- **Sync model**: client UUIDs, `updated_at`, `deleted_at` tombstones, last-write-wins. New synced tables need a migration with RLS, a SwiftData `@Model` conforming to `SyncedModel`, a `*Row` in `RemoteRows.swift`, and registration in `SyncService` and the model container in `LiftLogApp.swift`. `touch()` saves immediately.
- A workout is in progress only when `source = 'app'` and `ended_at` is null; web and imported workouts without an end time are finished.
- Web pages render on the server: use the viewer's zone (`userTimeZone()`, from a cookie) or a workout's own `timezone`, never the server's.
- Apple Health nutrition stays on the phone.

## Deploy / ops
- **Web**: Vercel, root dir `web`, `sourceFilesOutsideRootDirectory=true` (web imports `../shared`), install/build pinned to `npx --yes pnpm@11.21.0 ...`. `scripts/vercel_deploy.py` uploads files (`VERCEL_PROJECT`, `VERCEL_TOKEN`, Supabase URL/key, any `NEXT_PUBLIC_*`).
- **Database**: `scripts/supabase_migrate.py` applies migrations and the idempotent seed via the Management API.
- **iPhone**: CI publishes an unsigned `LiftLog.ipa` (public backend from `Config.example.xcconfig`) to the `ios-latest` release on every push to `main`, for SideStore (`docs/INSTALL.md`).
- **Sign-in**: see `docs/AUTH.md`. Secrets (access tokens, service keys) are never committed.
